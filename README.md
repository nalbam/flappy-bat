# Flappy Bat / 박쥐의 야간비행

Three.js와 순수 JavaScript로 만든, 빌드 과정이 필요 없는 GitHub Pages용 3D 플래피 게임입니다. 모든 동굴, 바위, 박쥐, 파티클은 런타임에 절차적으로 생성됩니다.

## 실행

`docs/main.js`는 `docs/input.mjs`, `docs/audio.mjs`, `docs/audio-events.mjs`, `docs/view.mjs`, `docs/game-rules.mjs`, `docs/game-core.mjs`, `docs/collision.mjs`, `docs/obstacle-generator.mjs`, `docs/flight-history.mjs`, `docs/rock-mesh.mjs`, `docs/bat-model.mjs`를 불러오는 native ES module(`<script type="module">`)입니다. 브라우저는 `file://`로 연 페이지에서 module을 불러오지 않으므로 `docs/index.html`을 직접 열면 게임이 시작되지 않습니다. 반드시 HTTP 서버로 엽니다.

1. 저장소 루트에서 정적 서버를 실행합니다.

   ```bash
   python3 -m http.server 8000
   ```

2. 브라우저에서 `http://localhost:8000/docs/`를 엽니다.

설치나 빌드는 필요 없습니다. Three.js는 CDN에서 불러오므로 인터넷 연결이 필요합니다.

## 조작

- 박쥐는 화면 왼쪽에서 오른쪽으로 날아가는 횡스크롤로 진행하며, 동굴과 기둥이 오른쪽에서 왼쪽으로 흘러옵니다. 카메라는 비행 평면을 옆에서 기울이지 않고 고정해서 비추므로, 기둥 틈의 높이가 비행 중에 바뀌어 보이지 않습니다.
- 날갯짓: `Space` / `ArrowUp` / 클릭 / 탭. 키를 한 번 누를 때마다 한 번만 날갯짓하며, 누르고 있어도 반복되지 않습니다.
- 시작: 시작 화면에서 날갯짓 입력을 하거나 `날아오르기` 버튼을 누릅니다. 버튼에 포커스한 상태에서는 `Enter`도 동작합니다. 시작 입력도 일반 날갯짓과 같은 상승 속도를 한 번 줍니다.
- 빠른 재시작: 충돌하면 결과 카드에 통과한 기둥 수, 최고 기록, 그 비행의 `SEED`, 최근 비행 목록이 표시됩니다. 새로 `Space`·`ArrowUp`을 누르거나, 화면을 클릭·탭하거나, `다시 시작` 버튼을 누르면 한 번에 새 비행을 시작합니다. 충돌할 때 누르고 있던 키로는 재시작하지 않으므로 키를 뗐다가 다시 누릅니다.
- 일시정지: 비행 중에 `P` 또는 `Escape`를 누릅니다. 일시정지 화면에 `일시정지`와 재개 방법이 표시됩니다. 다시 `P`·`Escape`를 누르거나 `계속` 버튼을 클릭·탭하면 멈춘 자리에서 이어서 납니다. 버튼에 포커스한 상태에서는 `Enter`도 동작합니다. 재개는 날갯짓을 하지 않으므로 박쥐는 멈출 때의 속도로 이어서 납니다.
- 일시정지 중에는 `Space`·`ArrowUp`·클릭·탭이 아무 동작도 하지 않습니다. 날갯짓하지 않고, 재개하지 않으며, 재개한 뒤에 늦게 실행되지도 않습니다. `계속` 버튼에 포커스가 있어도 `Space`로는 재개하지 않습니다. 일시정지 키를 누르고 있어도 한 번만 동작합니다.
- 비행 중에 탭을 숨기면 자동으로 일시정지합니다. 탭이 다시 보여도 자동으로 재개하지 않습니다. 시작 화면과 결과 화면에서는 일시정지 키와 탭 숨김이 상태를 바꾸지 않습니다.
- 현재 점수는 비행마다 초기화됩니다. 브라우저 `localStorage`에는 다음 세 키를 따로 저장합니다.

  | 키 | 값 |
  |---|---|
  | `flappyBatBest` | 최고 점수 |
  | `flappyBatMuted` | 음소거 설정(`1`·`0`) |
  | `flappyBatRecent` | 최근 비행 5개의 점수와 seed. JSON 배열 `[{"score":점수,"seed":번호}]`이며 최신 비행이 앞입니다. |

- 최근 비행: 비행이 끝날 때(충돌)마다 점수와 seed를 최근 기록 맨 앞에 추가하고, 최근 5개만 `flappyBatRecent`에 저장합니다. 6번째 비행부터는 가장 오래된 기록이 빠집니다. 결과 카드의 `최근 비행` 목록은 최신순으로 점수와 `SEED <번호>`를 보여 줍니다. 기록은 새로고침 뒤에도 유지됩니다.
- 저장소를 쓸 수 없거나(차단·용량 초과) 저장된 최근 기록이 깨졌으면 빈 기록으로 시작합니다. 게임은 그대로 동작하고, 그 페이지 안에서는 메모리의 기록이 계속 쌓입니다. 저장값의 항목 중 점수가 0 이상 정수가 아니거나 seed가 0~4294967295 정수가 아닌 항목은 버리고, 나머지 올바른 항목만 씁니다.
- 소리: 받아들여진 날갯짓(시작·재시작 포함), 점수 1점, 충돌마다 효과음이 한 번 납니다. 효과음은 Web Audio로 실행 중에 만들며 오디오 파일을 쓰지 않습니다. 첫 키·클릭·탭 입력 전에는 오디오를 시작하지 않습니다. 브라우저가 오디오를 재개하는 동안 받은 효과음은 재개가 끝나면 걸린 시간과 관계없이 한 번 재생합니다. 재개가 실패하거나 재개 전에 일시정지·탭 숨김·음소거가 일어나면 그 효과음은 버립니다. 일시정지·탭 숨김·음소거는 나고 있는 소리와 예약된 소리를 바로 멈추고, 재개나 음소거 해제 때 지난 소리를 재생하지 않습니다.
- 음소거: 모든 상태(`ready`·`running`·`paused`·`over`)에서 `M`을 누를 때마다 소리를 켜고 끕니다. HUD의 `소리` 카드가 `켜짐`·`꺼짐`·`없음`을 글자로 표시합니다. 설정은 최고 점수와 다른 `localStorage` 키(`flappyBatMuted`)에 저장되어 새로고침 후에도 유지됩니다. 저장소를 쓸 수 없으면 그 페이지 안에서만 유지됩니다.
- Web Audio를 지원하지 않거나 오디오를 시작할 수 없는 브라우저에서는 소리 없이 게임이 그대로 동작하고 HUD에 `없음`이 표시됩니다. 소리는 게임 모델과 고정 tick 결과를 바꾸지 않습니다.
- 결과 카드의 `SEED` 번호는 그 비행의 장애물 배치 번호입니다. `?seed=<번호>`로 같은 배치를 다시 플레이할 수 있습니다([장애물 생성과 seed](#장애물-생성과-seed)). `최근 비행` 목록의 각 `SEED <번호>`는 같은 페이지를 `?seed=<번호>`로 다시 여는 링크입니다. 다른 query 값은 유지합니다. 링크를 클릭·탭하면 새 비행을 시작하지 않고 페이지만 이동하며, 이동한 페이지는 시작 화면에서 그 seed로 비행합니다. 링크에 포커스한 상태에서 `Enter`는 링크를 열고, `Space`는 링크를 열지 않고 기존처럼 다시 시작합니다.
- 운영체제에서 동작 줄이기(`prefers-reduced-motion`)를 켜면 충돌 시 화면 흔들림을 끕니다.

## 게임 규칙과 시간 처리

| 파일 | 역할 |
|---|---|
| `docs/game-rules.mjs` | 고정 tick, 중력, 날갯짓 속도, 속도 증가·상한, 박쥐 몸통 메시 크기와 기울기(`bodyPitch`), 동굴 바닥·천장, 수직 적분 |
| `docs/game-core.mjs` | `ready`/`running`/`paused`/`over` 상태와 시작(`startRun`)·일시정지(`pause`, `togglePause`)·재개(`resumeRun`), 박쥐 위치·속도, 점수, 비행마다 정하는 seed, 장애물 9개의 배치·재사용, 충돌 지점(`crash`), 프레임 시간 처리 |
| `docs/collision.mjs` | 몸통·기둥 윤곽(`bodyExtents`, `obstacleParts`)과 한 tick 이동 전체의 연속 충돌 판정(`sweepBody`) |
| `docs/obstacle-generator.mjs` | seed 난수원, 난이도 범위, 안전한 날갯짓 경로를 먼저 계획하고 그 주변에 틈을 놓는 장애물 생성기 |
| `docs/rock-mesh.mjs` | 충돌 윤곽에서 만드는 기둥·동굴 메시의 꼭짓점 데이터 |
| `docs/bat-model.mjs` | 박쥐 메시(`makeBat`, 페이지의 Three.js를 인자로 받음)와 경과 시간으로 계산하는 날갯짓 포즈(`createBatMotion`, `wingPose`) |
| `docs/flight-history.mjs` | 최근 비행 기록(`flappyBatRecent`, 최근 5개)의 추가(`addFlight`)·저장값 복구(`parseHistory`)·주입된 저장소 읽기·쓰기(`loadHistory`, `saveHistory`)와 seed 링크(`seedHref`) |
| `docs/input.mjs` | 키보드·포인터·버튼 이벤트를 날갯짓(`onFlap`)·일시정지 키(`onPause`)·음소거 키(`onMute`, `M`)·탭 숨김(`onHidden`)·버튼 동작으로 연결. 링크 위의 포인터 입력은 날갯짓으로 보내지 않음 |
| `docs/audio.mjs` | Web Audio 절차적 효과음(날갯짓·득점·충돌), 사용자 입력에서의 지연 생성·재개(`unlock`), 소리 차단(`silence`), 저장되는 음소거 설정(`createSound`) |
| `docs/audio-events.mjs` | 받아들여진 시작·날갯짓과 프레임의 점수 증가량·충돌 전이를 효과음 호출로 바꾸는 연결(`startWithSound`, `flapWithSound`, `advanceWithSounds`) |
| `docs/main.js` | 모델 결과를 Three.js 장면과 HUD에 반영하고 효과를 실행하는 어댑터 |

- 시뮬레이션은 1/120초 고정 tick으로 진행합니다. 같은 tick에 같은 입력을 주면 화면 주사율(30·60·144Hz 등)과 관계없이 결과가 같습니다.
- 한 프레임에서 따라잡는 시간은 최대 0.1초(12 tick)입니다. 그보다 긴 멈춤은 초과분을 버리므로, 박쥐가 순간 이동하지 않고 게임이 그만큼 느려집니다.
- 상태 전이는 다음과 같습니다. 표에 없는 입력은 상태와 모델을 바꾸지 않습니다.

  | 상태 | 날갯짓 입력 | `P`·`Escape` | `계속` 버튼 | 탭 숨김 |
  |---|---|---|---|---|
  | `ready` | 비행 시작(`running`) | 무시 | 표시 안 됨 | 무시 |
  | `running` | 날갯짓 | `paused` | 표시 안 됨 | `paused` |
  | `paused` | 무시 | 재개(`running`) | 재개(`running`) | 무시 |
  | `over` | 새 비행 시작(`running`) | 무시 | 표시 안 됨 | 무시 |

  `M`은 네 상태 모두에서 상태를 바꾸지 않고 음소거만 전환합니다.

- 탭이 숨겨진 동안의 시간은 어느 상태에서도 시뮬레이션하지 않습니다. 비행 중이었다면 `paused`가 되고, 탭이 다시 보여도 일시정지 화면에 머무릅니다.
- `ready`, `paused`, `over` 상태에서는 게임 모델(박쥐 위치·속도, 장애물, 점수, tick, 비행 시간, 거리, seed)이 진행하지 않습니다. `paused`에서는 `step()`·`advance()`가 아무것도 바꾸지 않고, 프레임 시간을 쌓아 두지도 않으며, `flap()`은 `false`를 반환합니다. 일시정지 중 화면은 계속 그리지만 날갯짓 포즈·파티클·흔들림 등 효과 시간도 멈춥니다. 충돌 뒤 박쥐가 떨어져 바닥이나 바로 아래 기둥 위에 멈추는 모습은 화면 효과입니다.
- 시작 입력(첫 시작과 재시작)과 재개(`resumeRun`)는 프레임 시계를 다시 시작합니다. 시작·재개 직후 첫 프레임은 0초로 처리하므로 `ready`·`paused`·`over`에서 보낸 시간은 비행에 들어가지 않습니다. 재개는 seed·장애물·속도·점수를 초기화하지 않고 상승 속도도 주지 않습니다.
- 현재 기울기의 박쥐 몸통 전체가 기둥의 뒤쪽 면을 벗어나면 기둥마다 한 번 득점합니다. 충돌한 tick에는 점수를 주지 않습니다.

### 충돌

모든 충돌은 비행 평면(z = 0)의 2D 윤곽으로 판정합니다. 화면의 기둥과 동굴 메시는 같은 윤곽에서 만듭니다.

- 몸통: `docs/bat-model.mjs`의 `makeBat`이 만드는 몸통 메시(반지름 0.43, 축별 배율 0.82·1.2·1, y축 -90° 회전)가 비행 평면에 만드는 타원입니다. 반폭은 0.43, 반높이는 0.516입니다. 타원은 화면의 박쥐와 같은 기울기 `bodyPitch(속도)`(-0.34~0.32 rad)로 기울어집니다.
- 충돌에 들어가지 않는 것: 머리, 귀, 날개, 파티클, 기둥 장식 돌, 동굴 벽의 돌. 몸통이 닿지 않았다면 날개가 기둥과 겹쳐 보여도 비행이 계속됩니다.
- 기둥: 반폭 0.62의 직사각형입니다. 틈 쪽 두 모서리는 0.16씩 잘려 있습니다. 위·아래 기둥 사이의 틈 높이와 위치는 장애물마다 생성됩니다([장애물 생성과 seed](#장애물-생성과-seed)). 틈 끝이 동굴 바닥 아래나 천장 위에 있는 기둥 조각은 만들지 않습니다. 생성기는 이런 틈을 만들지 않습니다.
- 동굴: 바닥 y = -1.32, 천장 y = 6.02입니다. 똑바로 선 몸통은 중심 높이 -0.804와 5.504에서 이 면에 닿습니다.
- 접촉 규칙: 몸통 윤곽이 기둥·바닥·천장과 한 점이라도 만나면 충돌입니다. 정확히 닿는 순간도 충돌입니다. 부동소수점 반올림만 흡수하도록 몸통을 1 + 1e-9배로 키워 판정하므로, 판정 위치의 차이는 1e-9 단위 미만입니다.
- 연속 판정: tick마다 몸통이 이동 전 위치에서 이동 후 위치까지 지나는 전체 경로를 검사합니다. 한 번의 이동이 기둥 폭보다 길어도 충돌을 놓치지 않습니다. 충돌하면 박쥐와 기둥은 몸통이 처음 닿은 위치에 멈춥니다. `game.crash`에는 닿은 점이 저장됩니다. 화면은 이 자세와 점에서 충돌 효과를 보여 줍니다.
- 화면과의 일치: 기둥 메시의 z = 0 단면은 충돌 윤곽과 같습니다. 기둥의 틈 쪽 끝은 비행 평면 위의 능선으로 끝나서 원근 화면에서도 틈 경계를 넘지 않습니다. 동굴 바닥·천장의 앞쪽 가장자리는 비행 평면 위에서 꺾이며, 그 앞의 암석은 어둡게 그립니다. 그래서 바닥·천장 충돌선이 화면의 밝기 경계로 보입니다. 원근 때문에 기둥 옆면은 화면에서 충돌 윤곽보다 몇 픽셀 넓어 보일 수 있지만, 좁아 보이지는 않습니다.

### 박쥐 캐릭터

카메라가 비행 평면을 옆에서 보므로, 박쥐는 측면에 투영되는 실루엣을 기준으로 만듭니다. 충돌하는 부분은 몸통뿐이고, 머리·귀·날개는 몸통 주위에 그리는 표현입니다.

- 몸통: 충돌 타원과 같은 메시입니다. `running`에서는 위치 `game.bat`과 기울기 `bodyPitch(속도)`를 그대로 그리며, 흔들거나 늘리지 않습니다.
- 머리·귀·눈: 머리 구는 몸통 외곽 안 앞 위쪽에 있고, 카메라 쪽으로 약 26° 돌아가 있습니다. 그래서 양쪽 눈과 두 귀가 옆에서도 겹치지 않습니다. 똑바로 선 자세에서 몸통 외곽 밖으로 나오는 얼굴 부분은 눈·눈썹·코의 0.1 미만입니다. 카메라 쪽 귀는 안쪽 면(녹슨 주황)이 보이고, 먼 귀는 어두운 실루엣으로 보입니다.
- 날개: 어깨·팔꿈치·손목과 손가락 4개의 관절 좌표 하나로 뼈대와 막을 함께 그립니다. 막 가장자리는 손가락 사이에서 손목 쪽으로 오목하게 들어갑니다. 날개 뿌리는 카메라 쪽 날개가 먼 날개보다 높게 기울어 있어 두 날개가 한 선으로 겹치지 않습니다.
- 날갯짓: 내려칠 때 손가락을 펼치고, 올릴 때 팔꿈치·손목·손가락을 접습니다. 날갯짓 한 번은 시작 화면에서 0.5초, 비행 중에는 0.3초입니다. 날갯짓 입력은 진행 중인 회복 동작을 0.12초 안에 마치고 바로 내려치게 합니다. 포즈는 프레임 수가 아니라 경과 시간으로 계산하므로, 날갯짓 입력 뒤에도 화면 주사율과 프레임 분할이 포즈를 바꾸지 않습니다.
- 몸통 반응: 머리와 날개 뿌리는 몸통 기울기 변화를 약 0.1초 늦게 따라갑니다. 충돌하면 첫 프레임은 닿은 자세를 그대로 보여 주고, 그다음 0.35초 동안 날개를 접습니다. 재시작하면 포즈를 처음 상태로 되돌립니다.
- 색: 털은 동굴 암석보다 어두운 자주·갈색, 막은 어두운 녹슨 빨강입니다. 밝은 색은 크림색 눈·송곳니와 녹슨 주황 코·귀 안쪽(`docs/style.css`의 `--cream`, `--rust`)만 씁니다.

## 장애물 생성과 seed

`docs/obstacle-generator.mjs`는 seed 하나로 한 비행의 장애물 열을 만듭니다. 같은 버전의 게임에서 같은 seed는 항상 같은 장애물 열(틈 높이 `gapHeight`, 틈 중심 `gapY`, 앞 기둥과의 간격 `spacing`)을 만듭니다. 생성 규칙·물리 값·`PLAY_VIEW.ahead`가 바뀌면 같은 seed의 배치도 바뀝니다. 생성기는 seed로 시작하는 자체 난수원(mulberry32)만 씁니다. 바위·재질·파티클의 `Math.random` 호출과 화면 프레임 분할은 장애물을 바꾸지 않습니다.

### 생성 방식

생성기는 통과할 수 있는 날갯짓 경로를 먼저 계획하고, 그 경로 주변에 틈을 놓습니다.

1. 경로는 시작 입력(tick 0, 높이 2.2, 상승 속도 5.1)에서 시작합니다. 게임 모델과 같은 tick 물리(`integrateVertical`, `speedAt`, `bodyPitch`, `bodyExtents`)로 진행합니다. 그래서 기둥마다 실제 도착 시각의 속도로 지나갑니다.
2. 경로는 목표 높이 아래로 내려가면 날갯짓합니다. 날갯짓은 초당 최대 4회입니다.
3. 다음 기둥의 중심이 박쥐 앞 9.5(모든 화면이 보여 주는 거리, `PLAY_VIEW.ahead`) 안에 들어오고 0.25초가 지나야 새 목표 높이로 바꿉니다. 계획 경로는 플레이어가 아직 볼 수 없는 기둥에 반응하지 않습니다.
4. 몸통이 기둥 옆을 지나는 모든 tick에서, 한 tick 동안 몸통이 쓸고 지나는 범위를 구합니다. 틈은 이 범위의 위·아래로 0.45(`SAFE_MARGIN`) 이상 떨어지게 놓습니다. 남는 범위 안에서 틈의 위치는 무작위입니다.
5. 다음 기둥의 경로는 앞 기둥을 벗어난 순간의 tick·높이·속도에서 이어집니다. 따라서 모든 기둥이 시작 입력부터 끊기지 않는 한 경로로 연결됩니다.
6. 원하는 높이 변화로 틈을 놓을 수 없으면 변화량을 1/2, 1/4, 0 순서로 줄여 다시 계획합니다. 계산량은 기둥마다 최대 4번의 계획입니다. 변화량 0(현재 높이 유지)은 항상 성공합니다. 각 계획은 다음 기둥에 닿을 수 있는 tick 전에 현재 높이의 호버링(목표 높이 −0.11~+1.25)으로 돌아와야 합니다. 이 호버링은 가장 느린 속도에서도 한 기둥을 지나는 동안 몸통 높이 범위가 약 2.2를 넘지 않습니다. 위·아래 여유 0.45를 더해도 가장 좁은 틈 3.3보다 작습니다. 시작 구간의 0번 기둥은 변화 한도가 0이므로 첫 계획(원하는 변화 전체)이 곧 현재 높이 유지이고 항상 성공합니다. 그래도 계획이 없으면 생성기는 예외를 던집니다. 테스트는 이 예외가 일어나지 않는 것을 확인합니다.

### 난이도와 한계

난이도는 기둥 번호(그 기둥에 도착할 때의 점수)에 따라 0번의 쉬운 범위에서 20번의 어려운 범위까지 선형으로 바뀌고, 그 뒤로는 유지됩니다. 속도는 기존처럼 비행 시간에 따라 증가합니다. 0~2번 기둥에는 아래의 시작 구간이 더해집니다.

| 항목 | 기본 식의 0번 값 | 20번 이후 |
|---|---|---|
| 틈 높이 `GAP_HEIGHT_RANGE` | 3.9~4.3 | 3.3~3.7 |
| 앞 기둥 중심과의 간격 `SPACING_RANGE` | 16~19 | 12.5~15.5 |
| 계획 경로의 목표 높이 변화 한도 `TARGET_SHIFT` | ±1.2 | ±2.4 |
| 속도 `speedAt` (시간 기준) | 7.2 (시작) | 약 31.6초 뒤부터 13.2 |

#### 시작 구간

처음 하는 사람이 첫 기둥 몇 개에서 바로 부딪혀 끝나지 않도록, 모든 비행의 처음 3개 기둥(0·1·2번, `INTRO_PILLARS = 3`)을 완만하게 만듭니다. 시작 입력부터 2번 기둥을 벗어날 때까지 약 7.2초입니다(seed 1 기준 tick 859). `difficulty(i)`는 i < 3에서 기본 식의 틈 높이 양 끝에 `INTRO_GAP_BONUS × (1 − i/3)`(`INTRO_GAP_BONUS = 0.8`)을 더하고, 목표 높이 변화 한도에 `i/3`을 곱합니다. 3번부터는 기본 식 그대로입니다.

| 기둥 | 틈 높이 (전 → 후) | 목표 높이 변화 한도 (전 → 후) | 간격·속도 |
|---|---|---|---|
| 0번 | 3.9~4.3 → 4.7~5.1 | ±1.2 → 0 (시작 높이 2.2의 호버링 유지) | 같음 |
| 1번 | 3.87~4.27 → 약 4.40~4.80 | ±1.26 → ±0.42 | 같음 |
| 2번 | 3.84~4.24 → 약 4.11~4.51 | ±1.32 → ±0.88 | 같음 |
| 3번 이후 | 기본 식 | 기본 식 | 같음 |

같은 seed(1~2000, 기둥 60개, 생성기 예외 0건)를 시작 구간 전후로 비교한 측정값입니다. 여유는 틈 높이에서 계획 경로가 기둥 옆에서 차지하는 몸통 높이 범위를 뺀 값입니다.

| 측정 | 0번 | 1번 | 2번 |
|---|---|---|---|
| 평균 틈 높이 (전 → 후) | 4.10 → 4.90 | 4.07 → 4.60 | 4.04 → 4.31 |
| 평균 여유 (전 → 후) | 2.50 → 3.27 | 2.26 → 2.76 | 2.28 → 2.55 |

0번 틈 중심과 시작 높이 2.2의 평균 차이는 0.70에서 0.37로 줄었습니다. 3번 이후의 틈 높이 분포는 같습니다. 계획 경로가 0번부터 달라지므로 3번 이후의 틈 위치(`gapY`)와 여유는 seed마다 달라질 수 있습니다(평균 여유 3번 2.30 → 2.28).

정한 내용과 이유는 다음과 같습니다.

- **"처음"의 범위: 첫 비행만이 아니라 모든 비행의 처음 3개 기둥.** 첫 비행에만 적용하면 같은 `?seed=`가 세션 상태에 따라 다른 배치를 만들어 재현 약속이 깨지고, 비행끼리 조건이 달라집니다. 처음 하는 사람은 재시작할 때마다 다시 시작 구간을 지나므로 모든 비행에 적용해야 효과가 있습니다. 생성은 기둥 번호만의 순수 함수이고 첫 비행 여부 같은 상태를 갖지 않습니다.
- **바꾼 값: 틈 높이와 목표 높이 변화 한도만.** 간격·`READY_SECONDS`·속도를 바꾸면 이후 모든 기둥의 도착 시각이 달라지고, 속도는 시간에 따라 정해지므로 숙련자 구간의 속도도 바뀝니다. 물리 값(중력, 날갯짓 속도, `BASE_SPEED`, `SPEED_GAIN`)을 바꾸면 조작감 전체가 바뀝니다. 그래서 `GAP_HEIGHT_RANGE`, `SPACING_RANGE`, `TARGET_SHIFT`, `DIFFICULTY_RAMP`, `READY_SECONDS`, `FIRST_OBSTACLE_X`, `SAFE_MARGIN`과 `docs/game-rules.mjs`는 그대로 둡니다. 0번의 목표 변화를 0으로 둔 것은 첫 틈이 시작 높이의 호버링 주변에 놓이게 하기 위해서입니다.
- **기록 경쟁을 지키는 방법.** 생성기는 기둥마다 난수 4개를 같은 순서로 뽑으므로, 같은 seed의 모든 기둥 x와 간격이 이전 버전과 같습니다. 따라서 기둥마다 도착 시각과 속도(`speedAt`)도 같습니다. 3번 이후의 난이도 범위도 같습니다. 그래서 점수 s ≥ 3인 비행은 시작 구간 3점에 이전과 같은 조건에서 얻은 s − 3점을 더한 것이고, 기존 기록과 비교할 수 있습니다. 이 이유로 최고 점수는 기존 `localStorage` 키 `flappyBatBest`를 그대로 씁니다. 모든 비행이 같은 시작 구간을 쓰므로 비행끼리도 조건이 같고, 같은 버전에서는 `?seed=<번호>`로 같은 배치를 재현합니다.

체감 난이도는 사람이 실제 기기에서 플레이해 확인해야 합니다. 테스트는 수치 범위와 통과 가능성만 고정합니다.

#### 고정 값

| 고정 값 | 값 | 의미 |
|---|---|---|
| `READY_SECONDS` | 2.5초 | 시작 입력부터 몸통이 첫 기둥에 처음 닿을 수 있는 시각. 첫 기둥은 x = 19.65(`FIRST_OBSTACLE_X`)에 있습니다. |
| `SAFE_MARGIN` | 0.45 | 계획 경로의 몸통과 틈 끝·바닥·천장 사이의 최소 거리. 호버링이 날갯짓하는 속도(5.1)에서 날갯짓 시점을 약 90ms 앞당기거나 늦춰도 되는 거리입니다. |
| `MIN_PILLAR_LENGTH` | 0.5 | 위·아래 기둥이 바닥·천장에서 최소로 보이는 길이. 틈 끝은 −0.82~5.52(`GAP_EDGE_RANGE`) 안에 있고, 틈 중심은 0.83~3.87 안에 있습니다. |
| `REACTION_SECONDS` | 0.25초 | 기둥이 화면에 들어온 뒤 계획 경로가 반응하기까지의 시간 |

### 장애물 재사용

장애물은 9개(`OBSTACLE_COUNT`)를 재사용합니다. 기둥이 x = −16(`OBSTACLE_RECYCLE_X`)보다 왼쪽으로 가면, 가장 오른쪽 기둥 뒤에 생성된 다음 간격으로 옮깁니다. 이때 틈과 생성 순서(`index`)를 바꾸고 `passed`를 초기화합니다. 그래서 기둥 순서와 간격이 유지되고 기둥마다 한 번만 득점합니다. 생성기는 마지막 기둥을 벗어난 경로 상태만 보관하고 생성 이력은 쌓지 않습니다. 화면은 틈 모양이 바뀐 기둥 메시만 다시 만들고, 이전 geometry를 `dispose()`합니다.

### seed 선택과 재현

- 일반 플레이: 비행마다 `crypto.getRandomValues`로 새 seed(0~4294967295 정수)를 뽑습니다. 결과 카드에 `SEED <번호>`가 표시됩니다.
- 재현: `http://localhost:8000/docs/?seed=<번호>`를 엽니다. 재시작해도 모든 비행이 같은 장애물 열을 씁니다. 번호가 0~4294967295 정수가 아니면 무시하고 콘솔에 경고를 남긴 뒤 비행마다 새 seed를 씁니다.
- 테스트와 코드에서는 `createGame({ seed: 번호 })`로 모든 비행에 같은 seed를, `createGame({ seed: () => 번호 })`로 비행마다 다른 seed를 줍니다.

### 생성 검사

seed의 장애물 열을 출력합니다(번호, x, `gapY`, `gapHeight`). 저장소 루트에서 실행합니다.

```bash
node --input-type=module -e "import { createObstacleGenerator } from './docs/obstacle-generator.mjs'; const g = createObstacleGenerator(20261031); for (let i = 0; i < 5; i++) { const { index, x, gapY, gapHeight } = g.next(); console.log(index, x.toFixed(2), gapY.toFixed(3), gapHeight.toFixed(3)); }"
```

seed의 계획 경로를 게임 모델(`createGame`의 `step`과 `sweepBody`)로 시작 입력부터 기둥 80개까지 재생해 충돌 없이 통과하는지 확인합니다. `FLAPPY_BAT_SEEDS`에 쉼표로 구분한 seed를 주면 기본 seed 16개에 더해 검사합니다.

```bash
FLAPPY_BAT_SEEDS=20261031,12345 node --test tests/obstacle-generator.test.mjs
```

통과하면 `# fail 0`이 출력됩니다. 실패하면 메시지에 seed, 충돌한 면과 tick이 나옵니다.

모든 테스트는 DOM·WebGL 없이 Node.js 내장 `node:test`로 실행합니다. Node.js 20 이상이 필요하며 패키지 설치나 앱 빌드는 없습니다. 저장소 루트에서 실행합니다.

```bash
node --test
```

## GitHub Pages 배포
